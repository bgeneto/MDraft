# User-editable AI Assistant prompts

**Status:** done
**Date:** 2026-11-02
**ADR:** `../adr/2026-11-02-user-editable-ai-prompts.md`

**Decision (2026-11-02):** Markdown, not YAML. The reader explicitly rejected a
YAML dependency to keep the binary small, and asks for a reset button that
restores every prompt safely after a bad edit. Open question 1 is therefore
answered; open questions 2–4 keep their defaults.

## Context and goal

The fourteen action prompts and the shared preamble are Rust string constants in
`src-tauri/src/ai/prompt.rs`. They were designed for insertion fidelity (see
`docs/adr/2026-10-28-ai-output-contract.md`), and the Summarize rewrite of
2026-11-02 showed the cost of that arrangement: changing one prompt needs a code
change, a rebuild and a release. A reader who writes in Portuguese, who wants a
different editorial voice, or who has a better prompt for their own discipline
cannot use it.

What should be true afterwards: the reader presses **Preferences → AI Assistant →
Edit prompts**, a file opens in the editor as an ordinary tab, they change the
wording, press Ctrl+S, and the next Generate uses it. Deleting the file — or
pressing **Reset to defaults** — returns everything to the built-in prompts. No
settings migration, no restart, no way for an edit to corrupt a document.

The only thing the file may not do is break the contract the application depends
on: the answer must still arrive inside `<mdraft-*>` so it can be streamed and
cleaned, and the document must still be described to the model as data.

## Scope and non-scope

### In scope

- One override file beside `settings.json` in the app config directory:
  `ai-prompts.md` (portable builds get it beside the executable through the
  existing `appDirectoriesOverride`).
- The shared preamble plus every action prompt, including the filename prompt in
  `src-tauri/src/ai/naming.rs` when that module is in the tree.
- A sparse override: a section that is absent uses the built-in prompt, so a
  partial file is valid and a future action keeps working with an old file.
- Validation with a message that names the file, the line and the problem.
- Three Preferences rows: **Edit prompts**, **Reset prompts to defaults**, and a
  note saying how many prompts are customised.
- **Reset is the safety net** the reader asked for: it rewrites the whole file
  from the built-in prompts in one write, so a file that no longer parses, or one
  whose edits broke an action, is recoverable without deleting files by hand. It
  is refused only while the prompts tab has unsaved changes (that is the one way
  it could lose work), and it works whether or not the assistant is enabled or
  configured.
- One fixed, non-editable sentence appended to every system message: the wrapper
  tag contract. The user controls the task, not the protocol.
- Tests: parser, round trip, `prepare` integration, the Preferences route and one
  end-to-end mock request proving the edited text reaches the provider.

### Non-scope

- Editing the wrapper tags, the `mdraft-notes` channel, `clean_answer`'s
  heuristics, `MAX_OUTPUT`, temperature, or the context budget. Those are the
  contract and the safety net.
- Counting the system prompt against the 8,192-token passage budget, or changing
  the panel's token count (which describes the passage only). The file is capped
  instead — see Risks.
- Per-workspace or per-document prompts, profiles, sharing/import-export, or
  localised prompt packs. One file per installation.
- A prompt editor window. The file is edited in the normal editor tab.
- `.yaml`/`.json` as the on-disk format — see the rejected alternatives; this is
  the one decision that needs the reader's answer before implementation.
- Sending the reader's prompts anywhere, logging them, or adding network
  activity of any kind.

## Approach and rejected alternatives

**Chosen: a Markdown override file, opened as an ordinary document.** The file is
`ai-prompts.md` in the app config directory, one `## <action-id>` section per
prompt, each body in a fence long enough to contain it:

````markdown
# MDraft AI prompts

Generated by MDraft 0.7.4. Change the wording, save, and the next Generate uses
it. Delete a section to fall back to the built-in prompt for that action.
Placeholders: {markup} {syntax_rule} {tone} {target_language} {target_markup}
{target_syntax_rule}. A placeholder that the action cannot fill is an error.

## preamble

```text
You are the writing assistant inside MDraft, …
```

## summarize

```text
You are summarizing a passage from the author's document. …
```
````

Why Markdown and not YAML: the application already is a Markdown editor, so a
`.md` file gets source highlighting, the preview, the outline, spellcheck,
Find/Replace, Format Document, Save, the crash-recovery journal, remembered tabs
and the disk poll **today**, with no new code. `languageFor()` maps `.md` to the
Markdown parser, and opening the file is the same `openPath()` the Help documents
already use. YAML or JSON would each need a second format end to end (see below).
Prose is also the one thing Markdown stores without quoting or indentation rules.

The parser is deliberately small and strict (`src-tauri/src/ai/prompts_file.rs`):
`# ` title ignored, `## ` starts a section, the following fenced block is the
prompt, a section id is an `AiAction` id or `preamble`/`suggestFileName`. Anything
else — unknown id, duplicate id, a section with no fence, an unterminated fence, a
placeholder the action cannot fill, a missing `{markup}`/`{syntax_rule}` in the
preamble — is refused with `ai-prompts.md line 42: unknown action "summarise"`.
Nothing is half-applied.

`prepare()` stays pure, which is what keeps its tests cheap: the file is read and
parsed in `ai_complete()` and passed in as `prompt::Overrides`. It is read on
every request rather than cached, so an external edit (Notepad++, another app) is
picked up with no invalidation logic; the file is kilobytes and the read is
microseconds against a multi-second model request.

The system message is assembled as
`[preamble] + "\n\n" + [action prompt] + "\n\n" + [tag sentence]`, where the tag
sentence is fixed Rust and names the action's `mdraft-*` tag. The built-in
prompts already end with that sentence; the duplication is deliberate, because it
is what lets a reader rewrite a prompt completely and still get a streamed,
cleaned answer. The existing `TagFilter` already degrades gracefully when a tag is
missing (it streams raw after 512 characters and `clean_answer` cleans it), so the
appendix is a quality guarantee, not a correctness crutch.

**Rejected: YAML.** Friendlier than JSON for prose, but it costs a Rust YAML crate
(`serde_yaml` is archived; `serde_yaml_ng` or `saphyr` would be new), and the
editor has no YAML top-level language: `DocumentLanguage` is a closed union of
four, `languageFor()` silently maps unknown extensions to Markdown, and a YAML
file opened today renders as Markdown and previews as garbage. Doing it properly
means a fifth document kind with no preview, no outline, no word sync and special
cases in Save As, export, image paste and the assistant's own language resolution
— 36 `asciidoc` references in `main.ts` alone show the blast radius — or a
separate modal CodeMirror surface, which is a second editor to style, focus-trap
and test. That is a lot of new machinery for prose we can already edit.
`@codemirror/language-data` does ship a YAML grammar, so highlighting alone is
free; the document kind is the expensive part.

**Rejected: JSON.** `serde_json` is already a dependency, but every newline in
every prompt becomes `\n` inside a quoted string. It needs the same fifth
document kind for highlighting, so it has YAML's cost with the worst editing
experience of the three.

**Rejected: prompts inside `settings.json`.** The app rewrites that file from its
own struct (`AppState::save`), so comments and formatting cannot survive, and it
is the one schema that must keep loading across versions. A map of long prose
strings there is also the least pleasant thing to hand-edit, and one bad save
would take the reader's Favorites, Recents and tab state with it.

**Rejected: a modal prompt editor in Preferences.** It needs its own undo, find,
save, validation display and focus handling, cannot be kept open beside the
document, and duplicates what the editor already does. It also contradicts the
button the reader asked for ("like Open the Markdown Reference").

**Rejected: one file per prompt.** Fifteen files to find, copy and reset.

## Risks and rollback

- **A reader deletes the "document is data" rule from the preamble.** Their own
  answers can then be steered by a hostile document. This is their own
  installation and their own instruction, the file header says what the rule is
  for, and no file operation becomes reachable (the assistant still has no
  tools). The `{markup}` and `{syntax_rule}` placeholders stay mandatory in the
  preamble, so the answer still arrives in the document's syntax.
- **A reader breaks streaming by dropping the tag.** Covered: the fixed appendix
  always names it, and `TagFilter` already handles a model that ignores it.
- **A prompt larger than the model's window.** Caps: 8,192 characters per prompt
  and 32,000 characters for the assembled system message, refused with a message
  rather than truncated silently. The passage budget is unchanged, and the
  non-scope says so.
- **Stale overrides after an upgrade.** A file generated by 0.7.4 keeps 0.7.4's
  wording for the sections it contains. The sparse rule limits the damage, the
  header records the generating version, and Preferences shows the count, so a
  reader can see that three prompts are theirs.
- **Test runs leak test prompts into the developer's profile.** `USER_STATE` in
  `scripts/test-all.mjs` must include the file; without it every AI suite that
  edits a prompt leaves it behind, exactly like the recovery-journal trap in
  AGENTS.md.
- **The prompts tab becomes a remembered tab** and can appear in `lastTabs` next
  launch; a missing file is already handled by the restore plan. It also enters
  the recovery journal, which is correct for a text file the reader edited.
- **Format Document on the prompts file.** Prettier does not reflow fenced code,
  so the prompts survive; a test parses a Prettier-formatted copy to prove it.
- **Rollback.** Delete `ai-prompts.md` (or press Reset): every override is
  sparse, so the built-ins return with no state to unwind. The code path is one
  function; reverting the commit removes the feature without touching settings.

## Tests and validation

| Layer | What it proves |
| --- | --- |
| Rust unit (`prompt::tests`, `prompts_file::tests`) | Round trip: `parse(serialize_defaults())` yields no overrides. Unknown id, duplicate id, missing/unterminated fence, unknown placeholder, a placeholder the action cannot fill, a missing `{markup}` in the preamble, CRLF, a BOM and an oversized prompt each fail with a message naming the line. A partial file overrides one action and leaves the other thirteen built-in. A default install keeps its built-in prompts and gains the fixed tag appendix; Improve and Ask get no appendix. |
| Mock AI (`npm run ai`) | The Preferences button creates and opens the file; all sections are present; editing `summarize` sends the edited text as the system message; a broken file shows its error in the panel; Reset is disabled while dirty and restores the defaults when clean. |
| Harness (`npm test`) | The developer's own prompts survive a run (the `USER_STATE` entry). |
| Manual | Launch, Edit prompts, change one word, save, Generate; delete the file, Generate, and confirm the built-in answer. |

The one measurement that proves it: with the file's `summarize` prompt replaced by
a unique marker sentence, the mock provider receives that marker in `system`, and
the answer still arrives inside `<mdraft-summary>`.

New Rust tests will change the counts quoted in `AGENTS.md` (`test:rust`, the
Testing table and the release checklist) and the mock-suite count; update all of
them in the same change.

## Acceptance criteria

- Preferences → AI Assistant → Edit prompts opens `ai-prompts.md` in a tab, with
  Markdown highlighting, and creates it from the built-in prompts on first use.
- Every prompt the assistant sends is visible in that file, one section each.
- Saving the file changes the next request with no restart; an external edit is
  picked up the same way.
- A malformed file produces one actionable error in the panel (file, line,
  reason) and never a half-applied prompt set.
- Deleting the file, or Reset to defaults, returns every prompt to the built-in
  text, proven by the round-trip test.
- The wrapper tag and the document-as-data rule cannot be removed from the
  protocol: a prompt that omits both still yields a wrapped, cleaned answer.
- `npm test -- --only ai` passes and no prompts file is left behind afterwards.

## Outcome

Implemented on 2026-11-02 and verified with the layers below: `cargo test`
271 passed / 270 on Linux (25 new tests), `npm test -- --only ai` 283/283,
`tsc --noEmit`, `eslint src` and `knip` clean. One defect the suite caught: the
Preferences note cached the prompt status for the panel's lifetime, so it went
on claiming the built-in prompts after a section had been saved; the cache is
now invalidated in `open()` (see the trap in AGENTS.md).

## Open questions

1. **Format: Markdown (decided 2026-11-02).** YAML is out: it would add a crate
   and a document kind, and the reader rejected the binary-size cost. Placeholders
   and the editable preamble are retained; the fixed tag appendix stays.
2. **Is the preamble editable at all?** Decided: yes, with the fixed tag appendix
   and the mandatory `{markup}`/`{syntax_rule}` placeholders, because the reader
   asked to keep every prompt feature.
3. **Reset while the prompts tab is dirty.** Decided: the button is disabled until
   the tab is saved or discarded, because overwriting a dirty buffer is the one
   data-loss path this feature could add. A file that no longer parses never
   blocks Reset.
4. **A toast after saving the prompts file** ("Prompts saved") — a nicety that
   needs the session to know the path. Default: not in this change; the next
   Generate is the proof.
