# AsciiDoc as a fourth native document format

**Status:** done
**Date:** 2026-10-17
**Reviewed:** 2026-10-17 — corrected against the code; the findings are listed
under [Review notes](#review-notes-2026-10-17).
**ADR:** `../adr/2026-10-17-asciidoc.md` (written with the implementation)

## Context and goal

MDraft edits three markups. Markdown is rendered in the webview by `marked`,
Typst is compiled by an external binary, and HTML is the file itself in a
sandboxed guest. AsciiDoc is only an export target: `default_export_formats()`
in `src-tauri/src/settings.rs` passes `-t asciidoc` to pandoc. Opening an
`.adoc` file today classifies it as Markdown (`languageFor()` in `src/main.ts`),
so a title written as `= Heading` is not a heading, `latexmath:[…]` is not a
formula, and the preview is the Markdown reading of AsciiDoc source.

The goal is that `.adoc` and `.asciidoc` behave as a fourth document language:
highlighted source, a live preview in the application's own type, KaTeX for
LaTeX mathematics, the same vertical scroll sync the other prose formats
already have, and clipboard copy and paste — including images — in AsciiDoc
when that is the document, through the pipeline in
[`2026-10-17-rich-paste.md`](2026-10-17-rich-paste.md).

## Scope and non-scope

### In scope

- Open, save, reload, tabs, outline, spellcheck, the default-extension
  preference and the open/save filters, for `.adoc` and `.asciidoc`.
- A preview of the AsciiDoc, drawn in `.markdown-body`, with admonitions,
  listings, local images and local `include::` of files that stay inside the
  document directory.
- Source highlighting for the constructs the Paragraph and Format menus insert.
- Listings coloured by the highlight.js build already in the app. A listing
  whose language is `mermaid` reuses the existing diagram pass.
- `latexmath` inline and display formulas drawn by the KaTeX already bundled.
  AsciiMath is left as text.
- Positional scroll sync, the transient blink, and click-in-preview, using the
  `data-line` anchors Markdown and Typst already use.
- Paragraph and Format commands that insert AsciiDoc, not Markdown markers.
- HTML export and print-to-PDF taken from that preview. Pandoc exports of an
  AsciiDoc buffer use pandoc's AsciiDoc reader.
- Clipboard, both directions, including images. Pasting rich text or an image
  into an AsciiDoc document writes AsciiDoc. Pasting AsciiDoc into Markdown,
  Typst or HTML writes that language. A bitmap, a drop, a pasted path or URL,
  and an image inside a rich fragment all go through the existing save pipeline
  and come out as `image::` or `image:`.
- The Files sidebar panel offers `.adoc` and `.asciidoc`. Its extension list is
  a hand-maintained allowlist in `src/sidebar.ts`; `typ` was once missing from
  it, and a format missing there cannot be opened from the panel at all.
- Preferences › Files › *Default File Extension* offers `.adoc` (and
  `.asciidoc`), a new document starts in AsciiDoc, and Save As suggests the
  matching name with the matching filter first. `languageLabel()` and the
  "Pasted as …" notice learn the fourth name too.
- Spellcheck treats AsciiDoc prose as prose and skips its markup: attribute
  entries, `image::`/`xref:`/`include::` macros, `latexmath:[…]`/`stem:[…]`, and
  the delimited listing, literal and passthrough blocks.
- The preview keeps the document title, `:toc:` and footnotes that
  `convert_embedded` emits, and the HTML export and print document carry the
  same AsciiDoc structure CSS as the preview.
- The welcome document, the package/Cargo/installer descriptions, the README and
  AGENTS.md stop claiming three formats.

### Non-scope

- A parser compiled into the Rust binary, `acdc`, `asciidork`, MathJax, the
  Asciidoctor stylesheet, or the Asciidoctor.js single-file executable.
- The extensions `.asc` (it collides with armored text) and `.ad`.
- OS file associations. None of the existing formats registers one, so this
  plan does not make MDraft the system default for `.adoc`.
- An AsciiMath renderer, a STEM script loaded from a CDN, HTTP `include::`, and
  any `ifdef` behaviour beyond what the processor does in secure mode.
- Reclassifying the editor's grammar or preview from the paste detector. As in
  the rich-paste plan, detection chooses the paste syntax only.
- RTF and OMML. Word and Office put HTML on the clipboard; that path already
  exists.
- A new image preference or a new download command. *Remote Images in Pasted
  Rich Text* and `download_image` stay as they are.
- Fixing the Paragraph/Format commands for Typst. They still insert Markdown
  markers today; this change adds an AsciiDoc branch and does not retarget
  Typst.

## Approach and rejected alternatives

The preview engine is `@asciidoctor/core` 4.1.1, imported only when an AsciiDoc
document is shown. The package's `exports` map exposes only `"."`, so the import
is `await import("@asciidoctor/core")`; Vite's `browser` condition resolves it to
`build/browser/index.js`. A direct
`@asciidoctor/core/build/browser/index.js` specifier fails with
`ERR_PACKAGE_PATH_NOT_EXPORTED`. That browser build is 990 496 bytes
unminified (measured from the 4.1.1 tarball), not the ~700 KB this plan first
estimated; the previous Opal build was about 1.74 MB. A dynamic `import()` keeps
it out of the startup chunk. It still ships inside the executable, because Tauri
embeds `dist/`: lazy loading saves startup, not the installer. That one chunk is
the accepted cost. Nothing else is added for AsciiDoc — no MathJax, no
Asciidoctor stylesheet applied, no second copy of KaTeX. Pin the version
exactly (`"@asciidoctor/core": "4.1.1"`), because 4.x output and its
extension API are still moving.

`load` runs with `sourcemap: true`, `standalone: false`, `safe: 'secure'` and
`base_dir: doc.directory`. Each block's `lineno` is written as `data-line` when
the location belongs to the buffer on screen. A **treeprocessor adds a unique
marker role** to every block (`mdraft-line-<n>`), and a **postprocessor rewrites
that role to `data-line="<n>"`** in the emitted HTML. This is deliberately not a
zip of `doc.blocks` against the DOM: `convert_embedded` prepends an `<h1>`
document title and a `<div id="toc">`, and appends a footnotes block, none of
which has an entry in `doc.blocks` — so a zip is off by one or more for any
document with a title, which the sample has by design. A marker also reaches
paragraphs nested inside sections, which a top-level zip would miss. The title
`<h1>` has no block entry either; the postprocessor gives it `data-line="1"`,
or the first scroll to the top of the source would land on the first section
and hide the title. Blocks that came from an include are not anchored: their
line numbers belong to the other file. If no marker survives, the map is
dropped and sync turns off, the same fail-safe `annotatePreviewLines` uses in
`src/markdown.ts`.

The HTML converter does **not** wrap `latexmath` in an element. Inline it emits
the plain text `\(...\)`; display it emits
`<div class="stemblock"><div class="content">\[...\]</div></div>`. The Markdown
preview's math pass works on the *source* before `marked`, so there is no
existing DOM pass to reuse. `asciidoc-preview.ts` therefore adds one:
`renderMathIn(host)` in `src/markdown.ts` walks text nodes, skips `pre`, `code`
and `script`, renders only the backslash delimiters with KaTeX into
`.math-inline` / `.math-display` (the classes the typography scale and the
export stylesheet already target), and leaves a malformed expression as a
`.math-error` like the Markdown renderer. It must not look at `$...$`: AsciiDoc
renders AsciiMath that way, and that is not TeX. Any MathJax `<script>` the
converter emits is removed by the DOMPurify profile the Markdown preview
already uses, and `standalone: false` emits none. The default value of
`:stem:` is AsciiMath; those expressions are left as text.

A custom `IncludeProcessor` reads included files through the existing
`read_document` command, and only after the target has been resolved inside the
document directory. `..` that escapes that directory, absolute paths, `file:`
URLs, UNC paths and `http:` targets are refused. The processor is registered on
a **per-load `Extensions.create()` registry** (the `extension_registry` option),
not globally, so two renders cannot see each other's document directory. It
tracks its own include stack and refuses a cycle, and it resolves a nested
include against the *included file's* directory while still enforcing the
document-directory boundary. Include attributes (`lines`, `tag`, `leveloffset`,
`indent`) are not honoured: the whole file is inlined. No new Rust command.
Includes are re-read on every render; that is acceptable for a preview, but a
debounced render on a large book should be measured before it is called done.

The highlighter is a CodeMirror `StreamLanguage` in this repository, using tags
the palettes in `src/syntax-themes.ts` already colour (`heading`, `strong`,
`emphasis`, `monospace`, `link`, `comment`, `processingInstruction`). There is
no official `@codemirror/lang-asciidoc`, and the community `lezer-asciidoc`
still does not colour emphasis, lists or formulas. A stream highlighter is a
few kilobytes and covers what the menu inserts. Listing, literal, passthrough
and inline-code tokens are named so `inCodeContext()` can see them **and** so
`src/spellcheck.ts` can add the same names to `SKIP_NODES`. If the grammar is
loaded through `asciidoc-language.ts` as a promise like the HTML and Typst
wrappers, the line scan covers the moment before it arrives.

### Clipboard

Rich paste already has one intermediate representation, one reader per source
and one renderer per destination. Images are resolved before rendering, and the
markup of a saved path lives in `imageSyntaxFor()` (`src/image-syntax.ts`).
AsciiDoc is the next reader and the next renderer. Today `planPaste()` renders
only Markdown, Typst or HTML, and `imageSyntaxFor()` has no AsciiDoc branch, so
a bitmap pasted into an `.adoc` buffer would be inserted as `![alt](path)`.

Pasting into AsciiDoc:

- HTML, Markdown or Typst on the clipboard is rendered by a new
  `render-asciidoc.ts`. AsciiDoc source that the detector is confident about is
  inserted byte-identical, the same rule `chooseSource()` already applies to
  Markdown and Typst.
- A standalone image — a clipboard bitmap, a drop, a pasted path or URL, or a
  paragraph whose only content is an image — becomes `image::path[alt]`. An
  image inside a sentence becomes `image:path[alt]`. A `]` or `,` in the alt
  text is escaped. Paths are forced relative, as they already are for HTML and
  Typst, because the preview resolves them from the document directory.
- Remote images inside a fragment keep the existing sink, the cap of 8 images,
  4 at a time, 8 seconds each, and the *Remote Images in Pasted Rich Text*
  preference.
- Inside a listing (`----`), a literal (`....`), a passthrough (`++++`) or
  inline monospace, the paste stays plain. The stream tokens carry names
  `inCodeContext()` recognises, with a line scan while the grammar is still
  loading.

Pasting AsciiDoc into the other formats:

- A bounded reader, `read-asciidoc.ts`, maps the structures the IR already
  has: titles, constrained and unconstrained quotes, lists and checklists,
  links, both image macros, `latexmath` (and `stem` when the document's
  notation is LaTeX), simple `|===` tables, quotes and listings. An admonition
  has no IR node, so it becomes a labelled quote; that is an approximation, not
  a lossless mapping. An `include::`, an `ifdef` or anything else the IR cannot
  represent is kept as a literal block, not dropped.
- Detection must not steal Typst. Both languages mark a title with `= `, so
  both scorers give it +4 and it cancels in the lead. Typst keeps its existing
  score; AsciiDoc is chosen only with a further score of at least 4 and a lead
  of 2, from signals Typst does not share: `image::` / `image:`, a
  `:name: value` attribute entry, an admonition label (`NOTE:`, `TIP:`,
  `IMPORTANT:`, `WARNING:`, `CAUTION:`), `|===`, `latexmath:[` / `stem:[`,
  `include::`, `xref:`.

Copying:

- Copy in the source pane stays CodeMirror's copy. The text is already
  AsciiDoc. The new reader is what turns that clipboard into Markdown, Typst
  or HTML when it is pasted into those documents.
- Copy in the preview is a new `copy` listener, not an existing path. When the
  selection hits `[data-line]` blocks, it writes `text/plain` as the source
  lines of those blocks and leaves `text/html` as the selection's HTML. The
  block's end line has to come from `data-line-end`; `data-line` alone marks
  only a start. A plain-text destination receives AsciiDoc, including
  `image::` macros, and a word processor still receives formatted HTML. A
  copied bitmap still wins over text, which is the order the image paste path
  already enforces. Whether this applies to Markdown/Typst too is Open
  question 7.

### Menu, outline and export

Paragraph and Format branch only for HTML today. An AsciiDoc buffer must not
fall through to `#` and `**`.

- Headings are `=` through `======`. The document title is `=`; Heading 1
  inserts `==` (the first section) unless Open question 1 decides otherwise.
  Increase and decrease heading rewrite that run.
- Strong is `*text*`, emphasis is `_text_`, code is `` `text` ``, strike is
  `[.line-through]#text#` with one CSS rule.
- A link is `url[text]`. An image inserted by the menu is
  `image::./image.png[alt]`.
- Inline math is `latexmath:[e^{i\pi}+1=0]`. Display math is a `[latexmath]`
  passthrough block.
- Lists are `* ` and `. `, tasks are `* [ ] `, a quote is `____`, a listing is
  `----`, a table is `|===`, a rule is `'''`.
- The five Alert items insert `NOTE:`, `TIP:`, `IMPORTANT:`, `WARNING:` and
  `CAUTION:`.
- Table of Contents inserts `:toc:` in the header. YAML Front Matter inserts
  an attribute block (`:title:`, `:author:`) and a short toast that AsciiDoc
  uses document attributes.

The outline scans `=` titles and skips delimited blocks — listing (`----`),
literal (`....`), passthrough (`++++`), example (`====`), sidebar (`****`),
quote (`____`), table (`|===`) and comment (`////`) — on the same shape as
`extractTypstHeadings` in `src/sidebar.ts`. A `= Title` at the top is the
document title; the outline shows it and the preview's own `<h1>` gives it the
same source line. Spellcheck stays on: AsciiDoc is prose, but
`src/spellcheck.ts` must learn the AsciiDoc token names and the markup skips.

The preview's CSS is not the export's CSS. `src/styles.css` styles the preview;
`wrapStandaloneHtml()` and `wrapPrintHtml()` carry their own inline rules and
never load `styles.css`. The AsciiDoc structure rules therefore exist twice:
the preview copy in `src/styles.css`, and one `ASCIIDOC_CSS` constant used by
both export wrappers. They sit beside each other and must stay in step. The
rules are: the admonition table reset (the Markdown preview's
`.markdown-body table` gives every admonition a border and `display:block`),
`.checklist`, block titles, the `#toc` box, quote attribution and
`.line-through`. Asciidoctor's own stylesheet is still not shipped.

HTML export and print-to-PDF call the AsciiDoc preview. `buildExportArticle()`
must not send an AsciiDoc buffer through `renderPreview()`, which is the
Markdown renderer. Pandoc exports of an AsciiDoc buffer use `-f asciidoc`
instead of the Markdown reader and its `tex_math_*` extensions. The pandoc
PDF-via-Typst entry still runs, with that reader. Two pandoc gaps are recorded
rather than solved: its AsciiDoc reader resolves an `include::` target against
pandoc's working directory (the preview resolves it in the document
directory), and it emits an empty `toc` div for `:toc:` unless `--toc` is
added. The ADR and the Export section of the README say so.

### Rejected alternatives

- **A parser compiled into the Rust binary.** Every launch would pay for it,
  including sessions that never open AsciiDoc. Typst was left as an external
  program for the same reason.
- **`asciidork`.** Its own list of unfinished work includes STEM, so formulas
  would not render.
- **`acdc` as WebAssembly.** The published editor tarball is 1.4 MB, and the
  demo loads MathJax from a CDN. Both conflict with the size and network rules.
- **Pandoc as the live preview.** The AsciiDoc reader is lossy for callouts,
  conditionals and includes, and pandoc is not always installed. Pandoc stays
  the export tool, which it already is.
- **The Asciidoctor stylesheet and MathJax.** The stylesheet fights the
  application's type, and MathJax is a second math library plus a request the
  application would make on its own. KaTeX and DOMPurify are already here.

## Risks and rollback

- **The browser build is young.** `@asciidoctor/core` 4.1.1 (5 October 2026)
  is a rewrite of the Ruby processor, not the Opal build it replaces. A
  conversion that looks plausible can drop a block. Mitigation: the CDP
  fixture asserts a title, an admonition, a formula with a real KaTeX fraction
  bar, and a local image, rather than trusting the library's own suite.
- **An include with no resolver drops chapters.** Mitigation: the processor
  is part of the first preview, not a follow-up. A target outside the
  document directory is refused, and the preview shows the processor's own
  message instead of reading the file. The processor also needs a cycle guard,
  nested resolution against the included file's directory, and a decision on
  include attributes; a self-including file would otherwise recurse for ever.
- **The embedded document is not `doc.blocks`.** `convert_embedded` emits an
  `<h1>` title, a `#toc` div and a footnotes block that have no block entry, so
  a block-to-DOM zip is off by one or more for any document with a title.
  Mitigation: marker roles plus a postprocessor, not a zip.
- **The sourcemap lines are not always the reader's lines.** The sourcemap
  skips block metadata, and an included block reports the other file.
  Mitigation: stamp only the locations whose file belongs to this buffer, and
  drop the whole map when no marker survives. Sync turns off; it does not
  scroll to the wrong block.
- **`latexmath` arrives as plain text.** The converter emits `\(...\)` and
  `\[...\]` with no wrapping element, and the Markdown math pass works on the
  source before `marked`. Mitigation: the new `renderMathIn(host)` pass, with
  tests for a fraction bar and for the `$...$` AsciiMath case that must stay
  literal.
- **An admonition is a table.** `.markdown-body table` gives it
  `display:block`, borders and padding. Mitigation: the
  `.admonitionblock > table` reset in the `src/styles.css` preview rules and
  in `ASCIIDOC_CSS`, checked in the preview, the HTML export and the print
  document.
- **`=` is also a Typst title.** A detector that scores it only for AsciiDoc
  will paste a Typst document as AsciiDoc, or the reverse. Mitigation: give
  the shared `= ` +4 to **both** scorers so it cancels in the lead; do not
  remove `scoreTypst`'s bonus, or a title-only Typst document becomes
  undetectable. AsciiDoc still needs 4 more and a 2-point lead from its own
  signals.
- **The Markdown image string is a pinned result.** Adding a branch in the
  wrong place would change `![alt](path)`. Mitigation: the new arm is only
  `language === "asciidoc"`, and the existing paste and image suites are run
  once to show they did not move.
- **Heading levels are not the same as Markdown's.** `=` is the document
  title, `==` is the first section. A Heading 1 command that inserts `=` at
  the top turns the line into the title, not a section. Mitigation: a decision
  in Open questions, and a test that presses Heading 1 in a document with an
  existing title.
- **Spellcheck sees markup as words.** Attribute entries, macros and listing
  code are prose to a plain tokenizer. Mitigation: `SKIP_NODES` and
  `extraSkips`, and a CDP check that `latexmath` and a listing produce no
  underline.
- **Pandoc's AsciiDoc reader has its own gaps.** It resolves `include::`
  against pandoc's working directory, not the document's, and it does not
  fill the `:toc:` div. Mitigation: documented as a fidelity gap, with
  `--toc` given as the export workaround. Do not claim the DOCX/PDF matches
  the preview for includes.
- **A preview copy has no end line.** `data-line` marks a start, not a
  range. Mitigation: stamp `data-line-end` from the block's source range, or
  copy only the start line to the next anchor; decide before shipping the
  copy feature.
- **The language union has no exhaustiveness check.** `editor.setLanguage`
  treats every value that is not `"markdown"` or `"html"` as Typst. A missed
  `"asciidoc"` branch colours the source with the Typst grammar and looks
  almost plausible. Mitigation: an explicit branch and the CDP suite's heading
  colour check on the `.adoc` fixture.
- **A conversion per keystroke costs more than `marked`.** The render is
  debounced at 200 ms and guarded by a token, but a large AsciiDoc book with
  includes re-reads every file on each pass. Mitigation: measure the fixture
  and a large document before calling it done; raise the AsciiDoc debounce to
  the HTML 300 ms if the measurement says so.
- **Rollback.** The feature is the new modules plus the `"asciidoc"` branches.
  There is no settings migration. Removing the npm dependency removes the
  chunk. The export target that already writes AsciiDoc is untouched.

## Acceptance criteria

- Opening `samples/asciidoc-tour.adoc` highlights a title differently from the
  body, previews the prose in the application's type, draws the `latexmath`
  formula with a visible KaTeX fraction bar, and moves the preview when the
  source is scrolled.
- An `include::` of a sibling file is inlined. A target that leaves the
  document directory with `..` is not read, and a self-include cannot recurse
  for ever.
- The startup bundle does not contain Asciidoctor or MathJax. The AsciiDoc
  chunk loads on first use, and the ADR records its measured size.
- Pasting HTML or Markdown into an AsciiDoc document writes AsciiDoc. Pasting
  AsciiDoc into Markdown, Typst or HTML writes that language. Pasting AsciiDoc
  into AsciiDoc is byte-identical.
- A bitmap, a drop, a pasted image path and an image inside a rich fragment
  are saved by the existing pipeline and inserted as `image::` or `image:`.
  The file exists and the preview loads it. Markdown's `![alt](path)` is
  unchanged.
- The Files panel lists `.adoc` and `.asciidoc`; *Default File Extension*
  offers AsciiDoc; a new document starts in AsciiDoc; Save As suggests the
  matching name and puts the AsciiDoc filter first.
- Spellcheck leaves markup, macros and listing code alone.
- The installer, package and Cargo descriptions, the welcome document, the
  README and AGENTS.md no longer say the editor handles three formats.
- Copying a selection in the preview puts the AsciiDoc source of those blocks
  on `text/plain`.
- The application makes no request at startup. A remote image is fetched only
  through `download_image`, under the preference that already governs rich
  paste.

## Open questions

1. **Heading levels.** `=` is the document title and `==` the first section.
   Default: Heading 1 inserts `==` and the document title stays a separate
   command; the outline still reads `=`. If Heading 1 must insert `=`, the
   front matter command has to own the only title.
2. **Math and diagram switches.** *Preferences › Markdown* owns
   `enableMath`/`enableMermaid`. Default: AsciiDoc obeys both and the section
   help text says "Markdown and AsciiDoc".
3. **AsciiMath.** Default: leave it as text. A converter would be a second
   math library, which this plan refuses.
4. **HTTP includes.** Default: refuse them. Only a file under the document
   directory is read.
5. **Extensions.** Default: `.adoc` and `.asciidoc` only, and both appear in
   the default-extension select. `.asc` stays unrecognised because it is also
   armored text.
6. **Setext titles.** Default: the outline reads `=` titles only, as the
   Typst outline reads `=` and not the function form.
7. **Preview copy.** Default: AsciiDoc only, with `data-line-end`; copying the
   rendered text is still what every other format does.
8. **Export fidelity.** Default: accept pandoc's AsciiDoc reader as it is, add
   `--toc` to the exported format's extra arguments, and document that
   `include::` is resolved by pandoc's working directory rather than the
   document's.
9. **A title-only document.** Both scorers give `= ` +4, so a document that is
   only a title is ambiguous in both directions. Default: accept the fallback;
   the editor's language decides, which is what the default extension was for.

## Implementation record (2026-10-17)

Implemented end to end, with three deviations from the plan and one discovery
worth keeping:

- **The title needed `attributes: { showtitle: "" }`.** `standalone: false`
  makes Asciidoctor set `notitle`, so `convert_embedded` omits the `<h1>` even
  though `doc.hasHeader()` is true. The plan's "convert_embedded prepends the
  title" was only true when `notitle` is clear. The preview and the CDP suite
  both check the title now.
- **The marker rewrite is a DOM pass, not a string postprocessor.** The
  treeprocessor still adds `mdraft-line-<n>` roles, but `asciidoc-preview.ts`
  rewrites them after DOMPurify, where `classList` and `dataset` are reliable.
  `data-line-end` is stamped at the same time.
- **Includes needed a `/C:/` → `C:/` path normalisation.** The browser build
  reports `base_dir`-derived paths with a leading slash before the drive; Rust's
  `DocumentPayload.directory` does not. Without the fold, every include was
  refused as "outside the document directory".
- **Measured chunk sizes:** the startup chunk is 771,058 bytes and contains no
  Asciidoctor; the lazy Asciidoctor chunk is 990,496 bytes, with a 371,248-byte
  sub-chunk for its stylesheet-bearing part. The startup bundle check is
  therefore a real assertion, not an assumption.
- **Measured checks:** Rust 79 total (78 run, 1 ignored); paste conversion 72;
  AsciiDoc 35; document tabs 69; export 35; smoke 93; rich paste 23; image
  syntax 14; syntax 7. `npm run build`, `npm run dist -- --no-portable`, the
  affected CDP suites and `cargo test` (with `TEMP`/`TMP` inside the workspace)
  passed.
- **Copy is AsciiDoc-only**, per Open question 7. It writes the source lines of
  the selected blocks to `text/plain` and keeps the selection's HTML.

## Review notes (2026-10-17)

These are the findings of the code review that produced the corrections above.
They are kept so a later session can see which claims were checked, not
assumed.

- `@asciidoctor/core@4.1.1` exports only `"."`; a `/build/browser/index.js`
  subpath import is not reachable. The browser build is 990 496 bytes
  unminified.
- `convert_embedded` (what `standalone: false` selects) prepends the document
  `<h1>` and the `#toc`, and appends footnotes. A `doc.blocks` ↔ DOM zip cannot
  work for the sample. The marker role/postprocessor is the fix.
- Inline `latexmath` is emitted as plain `\(...\)` text, and display math as
  `.stemblock > .content` containing `\[...\]`. There is no exported DOM math
  pass in `src/markdown.ts`; the Markdown one runs on the source.
- `decorateCodeBlocks` and `decorateLinks` in `src/markdown.ts` are private;
  reusing them requires exporting them. `addHeadingIds` must **not** run on
  AsciiDoc output — Asciidoctor's `sectids` are the `<<xref>>` targets.
- The classic html5 converter emits an admonition as
  `<div class="admonitionblock"><table>…`; `.markdown-body table` in
  `src/styles.css` makes that a bordered block. The checklist, block title,
  `#toc` and attribution selectors are also missing.
- The HTML and print exports never load `styles.css`; they carry their own
  inline CSS. A rule added only to `styles.css` does not reach them.
- `src/sidebar.ts` has its own extension allowlist, separate from
  `documentFilters`; `typ` was once missing from it.
- `src/spellcheck.ts` skips code by node name (`SKIP_NODES`) and markup by
  regex (`extraSkips`); AsciiDoc needs both.
- `src/editor.ts` writes Markdown markers in `setHeading`, `shiftHeading`,
  `toggleLinePrefix`, `setTaskState`, `insertToc` and `insertYamlFrontMatter`;
  branching only the `src/main.ts` handlers leaves those reaching for `#` and
  `- [ ]`.
- There is no `copy` listener in `src/main.ts` today; the preview copy is a new
  feature, not a small branch.
- `languageLabel()` and the "Pasted as …" extension mapping in
  `src/main.ts` are Markdown/Typst/HTML-only; a missed branch would tell an
  AsciiDoc document to save as `.md`.
